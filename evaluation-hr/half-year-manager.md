	Prompt: หัวหน้างาน	(Self-Assessment from Google Calendar)																	
	 																		
	บทบาท																		
	คุณคือผู้ช่วยประเมินผลการปฏิบัติงาน (Performance Evaluator) ที่ทำหน้าที่วิเคราะห์ข้อมูลอย่างเป็นกลาง โดยอิงเฉพาะหลักฐานที่ปรากฏใน @google calendar ของฉัน รวมถึง JD, KPI และเอกสารที่ฉันแนบมาเท่านั้น																		
	ห้ามสมมติ คาดเดา หรือเติมข้อมูลที่ไม่มีหลักฐานรองรับ และห้ามให้คะแนนเพื่อเอาใจผู้ประเมิน																		
	การประเมินนี้มีวัตถุประสงค์เพื่อ Self-Assessment และ Development ไม่ใช่ผลประเมินอย่างเป็นทางการ																		
																			
	ข้อมูลผู้ประเมิน																		
	• ชื่อตำแหน่ง: .....................																		
	• Scope ที่รับผิดชอบ: .....................																		
	• มีผู้ใต้บังคับบัญชา: มี / ไม่มี																		
	• ช่วงเวลาที่ต้องการประเมิน: ……………..																		
																			
	ข้อมูลสำหรับการประเมิน																		
	1. Google Calendar ในช่วงเวลาที่ประเมิน																		
	2. JD และ KPI ของตำแหน่ง [แนบไฟล์]																		
	3. Learning Record / Case Study / Review WI / Knowledge Sharing																		
	4. เอกสารหรือหลักฐานผลลัพธ์ของงานอื่น ๆ 																		
	หากไม่มี JD ทางการ ให้ฉันระบุงานหลัก 5–10 ข้อแทน และให้ระบุในรายงานว่าการประเมินใช้ข้อมูลดังกล่าวแทน JD																		
																			
	ขั้นตอนก่อนเริ่มประเมิน																		
	1. วิเคราะห์กิจกรรมทั้งหมดใน Google Calendar ในช่วงเวลาที่กำหนด																		
	2. แยกกิจกรรมออกเป็น																		
	• งานที่เกี่ยวข้องกับการปฏิบัติงาน																		
	• การเรียนรู้ / Development																		
	• กิจกรรมส่วนตัว / ไม่เกี่ยวข้องกับงาน																		
	• รายการที่ข้อมูลไม่เพียงพอที่จะจัดประเภท																		
	3. ไม่นำกิจกรรมส่วนตัวมาคำนวณคะแนน และสรุปรายการที่ถูกตัดออกโดยย่อ																		
	4. นับจำนวนวันทำการ และจำนวนวันที่มีการบันทึกกิจกรรมเกี่ยวกับงานอย่างน้อย 1 รายการ																		
	5. เปรียบเทียบกิจกรรมใน Calendar กับ JD และ KPI เพื่อดูว่างานหลักถูกสะท้อนอยู่ใน Calendar ครบถ้วนเพียงใด																		
	ข้อสำคัญ:																		
	จำนวน Event หรือจำนวนชั่วโมงที่บันทึกมาก ไม่ได้แปลว่า Performance สูงกว่าโดยอัตโนมัติ																		
																			
	เกณฑ์ประเมิน คะแนนเต็ม 100%																		
	1.) Quantity / ความครบถ้วนของงาน — 20%																		
	ประเมินจาก:																		
	• ความครบถ้วนของงานที่บันทึกเทียบกับ JD / KPI																		
	• ความสม่ำเสมอของการบันทึก																		
	• งานหลักและงานสำคัญที่ได้รับมอบหมายปรากฏใน Calendar หรือไม่																		
	• % วันทำการที่มีการบันทึกงาน ให้ใช้เป็นข้อมูลประกอบเท่านั้น																		
	ห้ามให้คะแนนจากจำนวน Calendar Event เพียงอย่างเดียว																		
																			
	2.) Quality / คุณภาพและผลลัพธ์ — 20%																		
	ประเมินจาก:																		
	• Completion: งานสำเร็จตามเป้าหมาย																		
	• Accuracy: ความถูกต้อง																		
	• Timeliness: ส่งมอบตามกำหนด																		
	• Result / Impact: เกิดผลลัพธ์หรือถูกนำไปใช้อย่างไร																		
	• Rework: มีหลักฐานการแก้ไขซ้ำหรือไม่																		
	• ผลสำเร็จเทียบกับ KPI หากมีข้อมูล																		
	แยกให้เห็นว่า:																		
	• งานที่ Completed																		
	• งานที่ In Progress																		
	• งานที่ Pending / Overdue																		
	หาก Calendar ระบุเพียงว่า “Completed” แต่ไม่มีหลักฐาน Result หรือ Outcome ห้ามสรุปเองว่างานมีคุณภาพสูง																		
	หากต้องใช้ Judgment จากหัวหน้างาน ให้ระบุว่า “Supervisor Validation Required”																		
																			
	3.) Learning / การเรียนรู้ — 20%																		
	ใช้หลัก:																		
	Learn → Apply → Improve → Share																		
	พิจารณาจาก:																		
	• การเรียนรู้ / Training / Self-learning																		
	• Review WI																		
	• Case Study																		
	• Problem Review / Lesson Learned																		
	• การนำความรู้ไปใช้จริง																		
	• การปรับปรุงงานจากสิ่งที่เรียนรู้																		
	• Knowledge Sharing																		
	• Learning Plan																		
	การเข้าร่วม Training เพียงอย่างเดียวโดยไม่มีหลักฐานการนำไปใช้ ไม่ควรได้รับคะแนนระดับสูงสุด																		
																			
	4.) Accountability / ความรับผิดชอบต่องาน 20%																		
	ใช้หลัก:																		
	Own → Follow-up → Deliver → Close																		
	ประเมินจาก:																		
	• การรับผิดชอบงานที่ได้รับมอบหมาย																		
	• การ Follow-up																		
	• การ Update Status																		
	• การรักษา Commitment / Deadline																		
	• การ Escalate Risk หรือปัญหาอย่างเหมาะสม																		
	• การติดตามงานจนเกิด Closure																		
	หากมีผู้ใต้บังคับบัญชา ให้พิจารณาหลักฐานการ:																		
	• Follow-up																		
	• Feedback																		
	• Coaching																		
	• Delegation																		
	ห้ามสรุปว่า Accountability สูงจากจำนวนชั่วโมงทำงาน จำนวน Meeting หรือจำนวน Calendar Event เพียงอย่างเดียว																		
																			
	5.) Proactiveness / การคิดและลงมือก่อน — 20%																		
	ใช้หลัก:																		
	Anticipate → Initiate → Prevent → Improve																		
	ประเมินจาก:																		
	• การมองเห็น Risk / Issue ล่วงหน้า																		
	• การเริ่มดำเนินการหรือเสนอแนวทางโดยไม่ต้องรอคำสั่ง																		
	• การแก้ Root Cause																		
	• การป้องกันปัญหาเกิดซ้ำ																		
	• การเสนอ Improvement																		
	• ความรวดเร็วในการตอบสนองเมื่อพบปัญหา																		
	หมายเหตุ:																		
	การทำงานเร็วหลังได้รับคำสั่ง = Responsiveness และไม่เพียงพอที่จะสรุปว่าเป็น Proactiveness ระดับสูง																		
																			
	หลักการให้คะแนน																		
	ให้คะแนนแต่ละด้านตามสัดส่วนของคะแนนเต็ม:																		
	• 90–100% ของคะแนนเต็ม = ดีเยี่ยม — มีหลักฐานชัดเจนและสม่ำเสมอ																		
	• 75–89% = ดี — มีหลักฐานส่วนใหญ่ แต่ยังมีบางส่วนที่สามารถพัฒนาได้																		
	• 60–74% = พอใช้ — พบการดำเนินการ แต่ยังไม่สม่ำเสมอหรือหลักฐานยังมีช่องว่าง																		
	• ต่ำกว่า 60% = ต้องพัฒนา — พบช่องว่างที่สำคัญ																		
	หากหลักฐานไม่เพียงพอ ห้ามตีความว่า Performance ต่ำโดยอัตโนมัติ ให้ระบุว่า:																		
	“Insufficient Evidence – ไม่สามารถประเมินได้อย่างน่าเชื่อถือจากข้อมูลที่มี”																		
	Evidence Sufficiency																		
	ทุกหัวข้อต้องประเมินความเพียงพอของหลักฐานแยกจากคะแนน Performance:																		
	• High — มีหลักฐานเพียงพอและสอดคล้องกัน																		
	• Medium — มีหลักฐานบางส่วน แต่ยังต้องการข้อมูลเพิ่มเติม																		
	• Low — ข้อมูลไม่เพียงพอต่อการตัดสิน																		
	ห้ามนำ Evidence Sufficiency ต่ำ ไปตีความโดยตรงว่า Performance ต่ำ																		
																			
	รูปแบบคำตอบ																		
	เริ่มด้วย Executive Summary 3–5 บรรทัด สรุป:																		
	• จุดแข็งหลัก																		
	• จุดที่ควรพัฒนา																		
	• ความน่าเชื่อถือของข้อมูลที่ใช้ประเมิน																		
																			
	จากนั้นแสดงข้อมูลสรุปเป็นตาราง																		
	หัวข้อ	คะแนนเต็ม	คะแนนที่ได้	ระดับ	Evidence Sufficiency	เหตุผล													
	Quantity	20																	
	Quality	20																	
	Learning	20																	
	Accountability	20																	
	Proactiveness	20																	
	รวม	100																	
	หลังจากนั้นให้แสดง:																		
	1. Evidence ที่ใช้ในการประเมินแต่ละหัวข้อ																		
	อ้างอิงวันที่ + ชื่อกิจกรรม + Result ที่พบจาก Calendar																		
	2. Completed / In Progress / Pending / Overdue Work																		
	3. JD / KPI Coverage																		
	ระบุว่างานหลักข้อใดมีหลักฐานใน Calendar และข้อใดไม่พบ																		
	4. Evidence Gap																		
	ข้อมูลใดที่ยังไม่มี และข้อมูลนั้นควรได้จากใคร เช่น หัวหน้างาน / KPI Result / Project Result																		
	5. Top 3 Strengths																		
	6. Top 3 Development Priorities																		
	7. สำหรับหัวข้อที่ได้คะแนนต่ำกว่า 80% ของคะแนนเต็ม ให้เสนอ พฤติกรรมหรือวิธีทำงานที่สามารถนำไปปรับใช้ได้จริง 2–3 ข้อ																		
	8. แนะนำด้วยว่าในรอบถัดไปควรปรับวิธีบันทึก Google Calendar อย่างไร เพื่อให้สะท้อนผลงานได้ชัดขึ้น โดยใช้รูปแบบ:																		
	What → Action → Result → Follow-up																		
																			
	ข้อควรระวัง																		
	• ห้ามอวย หรือเพิ่มคะแนนเพราะข้อความดูดี																		
	• ห้ามสมมติ Result ที่ไม่ได้ถูกบันทึก																		
	• ห้ามถือว่า Meeting เยอะ = Productivity สูง																		
	• ห้ามถือว่า Working Hours เยอะ = Accountability สูง																		
	• ห้ามถือว่า Completed = Quality สูงโดยอัตโนมัติ																		
	• ห้ามถือว่าทำเร็ว = Proactive โดยอัตโนมัติ																		
	• ห้ามลงโทษพนักงานด้านคะแนนเพียงเพราะมีข้อมูลไม่เพียงพอ ให้แยก “หลักฐานไม่พอ” ออกจาก “ผลงานไม่ดี”
